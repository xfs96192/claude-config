# 银行理财产品申赎分析与流动性预测

## 概述

此 skill 用于分析银行理财产品的申购赎回数据，核心功能：
1. 自动识别和合并多个时间点导出的申赎 Excel 文件
2. 过滤母产品（排除子产品），汇总行内+行外申赎金额
3. 计算考虑锁定期后的**可赎回申购金额**和**累计赎回率**
4. 基于赎回率情景预测未来流动性需求

## 使用方式

### 快速开始

调用捆绑脚本一步完成全部分析：

```bash
python3 <skill-dir>/scripts/redemption_analysis.py <数据目录> \
  --product-name "<产品名称关键词>" \
  --product-start <成立日期> \
  --pre-total-sub <前期申购总额_亿> \
  --lockup-days <锁定期天数> \
  --scenarios "0.40,0.50,0.65" \
  --forecast-months 6
```

### 参数说明

| 参数 | 必需 | 说明 | 示例 |
|------|------|------|------|
| `directory` | 是 | Excel 文件所在目录 | `.` |
| `--product-name` | 推荐 | 产品名称关键词，用于过滤 | `灵动1年` |
| `--product-start` | 推荐 | 产品成立日 YYYY-MM-DD | `2024-06-06` |
| `--pre-total-sub` | 视情况 | 数据起始日之前的累计申购（亿）。若数据不完整则必填 | `12.8` |
| `--lockup-days` | 否 | 锁定期天数，默认 365 | `365` |
| `--scenarios` | 否 | 赎回率情景，逗号分隔 | `0.40,0.50,0.65` |
| `--forecast-months` | 否 | 预测月数，默认 6 | `6` |

### 参数收集流程

在运行脚本前，从用户处获取以下信息：

1. **产品名称关键词** — 如果目录下有多个产品数据，需要过滤。如"灵动1年"。
2. **产品成立日** — 用于计算锁定期满日。如用户不知道，可从数据推断或询问。
3. **前期申购总额** — 最重要：数据文件起始日期**之前**的累计申购金额。
   - 如果第一个数据文件的日期是 2025-05-07，而产品是 2024-06-06 成立的，
     则需补充 2024-06-06 ~ 2025-05-06 期间的申购金额。
   - 假设这段时间内申购是**均匀分布**的，用于计算每日新增可赎回金额。
   - 如果不需要补充前期数据（数据覆盖完整），传 `--pre-total-sub 0`。
4. **锁定期天数** — 默认 365 天（1年）。持有期型产品通常为 365 天。
5. **赎回率情景** — 默认三档：乐观 40%、基准 50%、悲观 65%。

### 输出文件

脚本会在数据目录生成以下文件（名称基于 `--output-prefix`，默认 `赎回分析`）：

| 文件 | 内容 |
|------|------|
| `{prefix}_申赎明细.xlsx` | 每日申购、赎回、净申赎金额 |
| `{prefix}_赎回率底表.xlsx` | 每日可赎回金额、累计赎回、累计赎回率 |
| `{prefix}_流动性预测.xlsx` | 未来逐日新增可赎回 + 多情景赎回流出预测 |
| `{prefix}_趋势图.png` | 三面板趋势图（申赎柱状图、累计对比、赎回率预测） |

## 分析原理

### 累计赎回率定义

```
累计赎回率 = 累计赎回金额 / 可赎回申购金额 × 100%
可赎回申购金额 = 申购日期 ≤ (当前日期 - 锁定期) 的所有申购之和
```

- **可赎回申购金额**：所有持有时间已超过锁定期、客户可以随时赎回的申购资金
- **累计赎回率**衡量的是"已满锁定期的那部分申购中，有多少比例被赎回了"

### 预测模型

- 每日新增可赎回金额 = 365天前（1年前）的申购金额（脚本中已有准确数据）
- 累计赎回率按 S 型曲线收敛到给定的终端赎回率
- `decay=0.03`：约30天后达到终端值的~63%，约100天后基本收敛
- 当日赎回 = max(0, 目标累计赎回 - 已赎回累计)，确保累计赎回率单调上升

### 前期数据假设

数据起始日之前的申购总额按**均匀分布**分摊到每日。这意味着：
- 可赎回金额的增速在前期是线性的
- 如果实际申购集中在某几个月，赎回率的拐点会相应移动
- **但终点不受影响**：当所有前期申购都满1年后，可赎回金额总额是正确的

## 运行后汇报

分析完成后，向用户汇报以下内容：

1. **数据概况**：文件数、日期范围、交易天数、涉及产品
2. **当前状态**：可赎回金额、已赎回金额、累计赎回率
3. **近期趋势**：近7/30天赎回率变化、日均赎回金额
4. **月度汇总表**：历史每月申购/赎回金额及月末赎回率
5. **预测结论**：三情景下未来3/6个月赎回流出、峰值月份
6. **流动性建议**：基于基准情景给出应准备的流动性金额

## 数据格式兼容性

脚本自动适配以下列名变体：
- 日期列：包含"日期"的列
- 产品名称列：包含"简称"或"名称"的列
- 申购列：包含"行内"+"申购" 或 "行外"+"申购"
- 赎回列：包含"行内"+"赎回" 或 "行外"+"赎回"
- 金额格式：自动处理千分位逗号（如 `201,338,357.06`）

## 常见问题

### 多个文件有重叠日期
脚本会自动去重（按 确认日期+产品简称 保留第一条）。

### 文件包含多个Sheet
脚本自动扫描所有Sheet，提取符合申赎格式的数据。

### 数据中包含多只产品
使用 `--product-name` 过滤，不传则不过滤。子产品（名称含"子"）默认排除。

### 前期数据不是均匀分布
这是模型的局限性。重要结论应注明"假设前期申购均匀分布"。如有前期申购的月度分布数据，可以手动构建完整序列后使用脚本的其他功能。
